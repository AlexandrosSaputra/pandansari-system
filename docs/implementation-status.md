## Alur yang telah memiliki implementasi

- Per 28 Oktober 2026, modul AI Insight khusus Superadmin dapat membuat prediksi untuk minggu depan, bulan depan, atau sampai tanggal tertentu. Data riil yang sudah dirapikan mencakup 6.032 observasi mingguan, 208 minggu, 29 SKU, dan tiga outlet; importer CSV idempoten memetakan sumber `Baso`, `Minuman`, dan `Pop Mie` ke Outlet 1–3. Setiap SKU membandingkan `lag_1`, rata-rata bergerak 4 minggu, musiman 52 minggu, dan rata-rata musiman 3 tahun berdasarkan holdout 52 minggu; metrik agregat seluruh kandidat ditampilkan agar pemilihan model dapat diaudit. Safety stock dapat diatur manual atau dihitung dari RMSE, lead time, dan target service level 90%/95%/97,5%/99%. Rekomendasi mentah dihitung dari prediksi permintaan, safety stock terapan, dan stok tersedia, lalu dibulatkan ke ukuran kemasan; lead time menghasilkan tanggal pemesanan paling lambat dan status keterlambatan. Hasil disimpan terpisah serta tidak mengubah saldo, transfer, atau mutasi stok. API dan halaman AI Insight menandai umur data serta jumlah minggu tanpa observasi sebelum target agar data usang tidak dianggap setara dengan data mutakhir. Penjelasan opsional mendukung OpenAI Responses API atau Ollama; kegagalan provider memakai penjelasan deterministik tanpa menggagalkan forecast.
- Per 28 Oktober 2026, `ai-service/` memiliki eksperimen Random Forest deterministik dengan fitur lag, rolling average, musiman, tren, outlet, dan SKU. Promotion gate hanya memakai validation set minggu 105–156: Random Forest menghasilkan MAE 4,8905 dan WAPE 23,4853%, sedangkan baseline terpilih menghasilkan MAE 4,7785 dan WAPE 22,9476%. Perbaikan relatif -2,3431% tidak memenuhi gate minimum 2% dan MAE juga lebih buruk, sehingga Random Forest tidak dipromosikan. Pada test set minggu 157–208 Random Forest memang lebih baik, tetapi hasil test hanya dicatat sebagai konfirmasi dan tidak dipakai membalik keputusan atau memilih hiperparameter.
- Header katalog dan keranjang memakai komponen bersama dengan ikon, judul, keterangan, badge, dan garis pemisah. Aksen lavender menandai katalog/unit, sedangkan biru menandai keranjang. Footer katalog memiliki rentang jumlah item, indikator halaman aktif, dan tombol panah berlabel aksesibel; tombol nonaktif pada batas halaman. Tampilan footer membungkus pada layar kecil. - Ruang POS/Ticketing mengikuti tinggi viewport dinamis (`100dvh`) sehingga halaman transaksi tidak perlu digulir. Pada desktop, katalog dan keranjang berdampingan dengan tinggi sama; masing-masing daftar mengisi ruang tersisa dan dapat digulir secara internal. Header, pagination, total, dan tombol pembayaran berada di luar area gulir daftar. Pada lebar layar sampai 1100 piksel, tombol pilihan Katalog/Keranjang menampilkan satu panel agar tidak bertumpuk; kedua panel tetap terpasang sehingga perpindahan tampilan tidak menghapus keranjang. Padding dan jarak kartu dipadatkan. Panel tetap dapat digulir sebagai fallback jika tinggi layar terlalu pendek untuk kontrol tetapnya. Halaman lain mempertahankan perilaku gulir semula. Penyesuaian layout ini belum diuji otomatis, build, atau browser sesuai arahan pengguna.
- Baris keranjang POS/Ticketing memiliki nomor urut `No. 01`, `No. 02`, dan seterusnya, yang mengikuti urutan item saat ini. Latar putih dan biru keabuan bergantian, disertai batas serta jarak antarbaris untuk memudahkan pemisahan visual. ## Kesenjangan utama terhadap proposal

1. Belum ada tabel `devices`, penerbitan dan rotasi token perangkat melalui UI, `scan_id`, retry idempoten, pairing POS, status perangkat, atau event real-time. Endpoint scan dasar yang ada masih memerlukan ID keranjang dan token Sanctum milik pembuat keranjang.
2. Seleksi kandidat deret waktu, safety stock berbasis service level, dan dashboard rekomendasi telah tersedia di Laravel. Eksperimen model pohon belum lulus promotion gate validation; eksperimen kandidat/hyperparameter berikutnya, endpoint inferensi produksi, penyimpanan artefak model, kalender hari libur, dan `visitor_daily` belum tersedia.
3. Jenis mutasi saat ini adalah `STOCK_IN`, `STOCK_OUT`, `TRANSFER_IN`, `TRANSFER_OUT`, dan `SALE`. Proposal juga memerlukan aturan untuk stok awal, penyesuaian, serta barang rusak.
4. Dashboard belum menampilkan omzet per outlet, produk terlaris, penjualan per jam/hari, prakiraan, dan rekomendasi pengadaan sebagaimana target proposal.
5. Bukti uji API end-to-end tersedia untuk alur inti, tetapi UAT browser pengguna dan suite browser end-to-end otomatis belum tersedia.

## Catatan kesesuaian istilah

Implementasi memakai role `superadmin`, `warehouse`, dan `admin`. Untuk kebutuhan proposal, `admin` berfungsi sebagai role petugas outlet/ticketing yang terikat pada satu unit operasional. Dokumentasi dan SKPL final perlu menyatakan pemetaan ini secara eksplisit agar tidak menimbulkan ambiguitas.
